# swayfin

A file manager for the user's Sway setup, replacing Dolphin.

## Goals

1. **Only the features the user asks for.** Don't add features, options, config files, menus or "nice to haves" on your own. If something seems missing, ask.
2. **Extremely fast startup.** Target: first frame in under 10 ms (measure with `WAYLAND_DEBUG=1`: time from `get_registry` to the first `wl_surface.attach`). Nothing may run before the first frame unless the frame needs it.
3. **High runtime performance.** Redraw only when something changes; never block the event loop on I/O.
4. **Look like the Sway setup:** minimal, OLED black, Tamzen bitmap font, 1px dividers, no gradients, shadows, rounding, animation or anti-aliasing.

## Stack

- Rust with `smithay-client-toolkit` on the pure-Rust `wayland-client` backend. Wayland/Sway only.
- No GUI toolkit (GTK/Qt), no GPU/EGL. The CPU draws into `wl_shm` XRGB8888 buffers.
- libxkbcommon is never linked (SCTK's `xkbcommon` feature is off; it costs ~1 ms of startup). Shortcuts use raw evdev codes (physical positions) and the raw modifier mask. For text entry, `src/xkb.rs` dlopens libxkbcommon (`xkbcommon-dl`) and compiles the saved keymap fd plus the locale's compose table (dead keys) when a text field first opens.
- Release profile uses fat LTO, `panic = "abort"` and strip. Keep dependencies minimal; every crate needs a reason.

## Architecture

- `build.rs`: parses `assets/fonts/TamzenForPowerline8x16{r,b}.bdf` into 1-bit glyph tables (`font_gen.rs`). No font files, fontconfig or freetype at runtime. It also builds `thumbd/` with CMake and passes its path in `SWAYFIN_THUMBD`. Without KF6 that step only warns.
- `thumbd/main.cpp`: `swayfin-thumbd`, a small Qt/KIO helper so swayfin itself never loads Qt. It also decodes image previews on its own thread with `QImageReader`: `F` fits the whole image (EXIF-upright, scaled decode, never enlarged), `R` returns a native-pixel region scaled to a size. Requests carry ids, and the newest one wins. It reads NUL-terminated paths on stdin, runs `KIO::PreviewJob` with all plugins (results are cached in `~/.cache/thumbnails`), and writes 16px premultiplied ARGB records to stdout. It runs headless (`offscreen` platform) with Qt's quit lock off. Files only: folders always use swayfin's own folder icon.
- `src/font.rs`: `Face` (`REGULAR`, `BOLD`), fixed 8x16 cells. Characters missing from the font fall back to the default glyph. Coverage is ASCII, Latin-1 and Powerline.
- `src/render.rs`: `Canvas` over the shm buffer: `fill`, `rect`, `text`. Every widget is built from these.
- `src/theme.rs`: colors taken from `~/.config/sway/config`. Don't use colors outside this file.
- `src/view.rs`: UI state (listing, scroll, hover, selection, a reserved 16px thumbnail column, pixel-art folder icon), layout, hit testing, input, drawing. Input methods return an `Effect`. No Wayland code here.
- `src/fs.rs`: reads a directory and formats every display string off the UI thread. Dotfiles are included only when toggled on (".", off at every launch); names listed in the folder's `.hidden` are always skipped, except `.hidden` itself. The listing arrives sorted by the folder's saved sort.
- `src/sort.rs`: sort order (Name, Date, Type = extension from the first dot), folders always first, ties by name. Each key has its own direction; the header's buttons sort by a key, or flip it if active. Saved per folder in `$XDG_STATE_HOME/swayfin/sort` (only folders differing from the default, Date newest first), loaded by the first directory read and written on a thread. A re-sort happens in place in `View::sort_by`, keeping selection and scroll; `App::loaded` re-sorts a listing whose read raced a sort change.
- `src/thumbs.rs`: 16px thumbnails on a worker thread. It first reads the shared freedesktop cache (md5 of the URI encoded like QUrl, `Thumb::MTime` must match) and box-filters it down. Misses go to `swayfin-thumbd`, which is spawned on first need. The app asks for the visible rows, then a screen below and above, whenever those rows change, and cancels on folder change.
- Image preview (`app.rs` `update_preview`): hovering a file's thumbnail slot shows the actual file, decoded by the helper to fit the window (at actual size if smaller), centered over the list dimmed 50%, with a 1px `#141414` border. The last 3 results are cached, including "not an image". While a preview is shown, the wheel zooms it around its center (1.25× per notch, effectively unbounded). The fitted image is stretched right away (nearest neighbor), then the helper returns a sharp `R` region decode of just the visible part. The helper keeps the current file's full-resolution decode for that; past native resolution, pixels are enlarged with hard edges.
- `src/player.rs`: audio playback with `mpv --no-video`, one file at a time. Pause/resume goes through mpv's IPC socket. mpv gets PR_SET_PDEATHSIG, and playback stops on folder change. Audio rows (`Entry.audio`, from `mime::by_name`) show a green play / red pause pixel icon instead of a thumbnail; click it or press "p" on a single selected audio file.
- `src/video.rs`: video previews through libmpv, dlopen'd on the first video hover. It uses the software renderer (`bgr0` into a 64-byte-aligned `FrameBuf`, then copied). Hovering a video's thumbnail slot plays it with sound and looping, fitted like images (never enlarged); the wheel zooms, via mpv's `video-zoom` once the video is bigger than the window. Only non-blocking libmpv calls are used, because the UI thread also renders. Wakeups go through a calloop `Ping`. The empty player (the thumbnail's aspect ratio, fitted) is drawn immediately, and libmpv load plus play run in an idle callback after that frame. Every frame mpv produces must be rendered, even ones not shown (`discard_frame`), or mpv's core stalls for about 0.5 s. `hwdec=vaapi-copy`, not `auto`: probing costs about 0.5 s. mpv only reports `dwidth`/`dheight` when they change, so the size is taken on `VIDEO_RECONFIG` for each new file; otherwise a same-size file never gets its size and stays black.
- `src/mime.rs`: freedesktop associations, run on workers. MIME type comes from `globs2` (weight, then literal, then longest pattern). Literals and `*suffix` globs are indexed, so `by_name` is cheap enough to run for every listed file, else a sniff for empty, text or binary. The default app comes from the mimeapps.list chain, then Added Associations, then `mimeinfo.cache`, walking parent types. It parses `.desktop` Exec (field codes, quoting) and wraps Terminal=true apps in `ops::terminal_argv()`. `set_default` edits `~/.config/mimeapps.list` in place.
- `src/ops.rs`: file jobs (move, delete, create folder, rename, duplicate, zoxide query), plus `zoxide add` for every folder the user navigates to (not refreshes), one worker thread each. Delete is permanent and recursive, never follows symlinks, keeps going past failures and reports the first one per item. Moves use `renameat2(RENAME_NOREPLACE)`; across file systems it copies to a temp name, renames that into place, then deletes the original. Name conflicts go to the UI as `JobMsg::Conflict`, and the worker blocks on the reply. Errors are collected as `path: reason` lines.
- `src/modal.rs`: centered modals (conflict, error summary, delete confirmation, text prompts for new folder, rename, duplicate (Ctrl+D on a single selection, prefilled with a free `name_N.ext`) and zoxide go-to, the "Open with" app picker), one at a time from a queue in `App`. While one is up, it takes all pointer input and keyboard shortcuts are off.
- `src/app/keyboard.rs`: `wl_keyboard`, shortcuts, key repeat (compositor rate), text keys for the name field, Ctrl+V paste (clipboard read on a thread).
- `src/app/clipboard.rs`: Ctrl+C/X/V with files on the system clipboard (`text/uri-list`, `x-special/gnome-copied-files`, `application/x-kde-cutselection`, plain-text paths), so it works with Dolphin, Nautilus and other swayfin windows. Paste goes into the current folder. Cut rows are drawn dimmed. After a cut is pasted and the move job is Done (matched by token), the paster clears the clipboard; the owner sees its source cancelled and refreshes. Setting the clipboard needs the last key-press serial (`key_serial`).
- History: every user navigation (`App::go`, including zoxide jumps) pushes a `ViewState` (path, scroll, selected names, last-touched row) onto `back` and clears `forward`. The mouse back/forward buttons (evdev 0x113/0x116 and 0x114/0x115) move through it, and `set_listing` restores the state when that folder's listing arrives. `set_listing` also keeps all interaction state (selection, anchor/cursor, press, double-click, drag rows) by name across a same-folder refresh, because refreshes can land at any moment.
- `src/watch.rs`: inotify on the shown folder (moved on navigation) triggers `refresh`, throttled to one per 100 ms while changes continue. `refresh` always reloads `nav_path` (the latest navigation), so it never undoes a navigation still loading.
- `src/downloads.rs`: downloads redirect. Shift+D sets the shown folder as the target, or turns it off if it already is (or the folder is the downloads folder). One redirect for all windows: the target path is in `$XDG_RUNTIME_DIR/swayfin/downloads` (replaced atomically, removed when off), which every window watches to show a down arrow and the folder in the header. The moving is done by `swayfin --downloads` (spawned from `/proc/self/exe`, own process group, single instance by flock on `downloads.lock`), so it outlives the windows and exits when the state file is removed. It watches XDG_DOWNLOAD_DIR for `IN_CLOSE_WRITE`/`IN_MOVED_TO` and moves a name 500 ms after its last event, skipping dotfiles, browser partials (`.part`, `.crdownload`, …) and names whose partial still exists (Firefox's placeholder). Taken names become `name_N.ext` (`ops::move_free`).
- `src/app/dnd.rs`: drag and drop over `wl_data_device`. We offer `text/uri-list`; Ctrl held when the drag starts makes it copy-only, because Sway/wlroots deliver no keys during a drag, so Ctrl at drop time can't be seen. Any local-file drop (from ourselves, other swayfin windows or other apps) onto a folder row goes into that folder, elsewhere into the current folder, as a move or copy (`ops::spawn_transfer`). The offer is `finish`ed only when that job's `Done` (matched by token) arrives, and the source refreshes on `dnd_finished`. Ctrl+press toggles the selection on release, so Ctrl+drag doesn't change it.
- `src/app.rs`: Wayland state and handlers. `draw()` repaints and commits. It runs on configure, or on a state change paced by frame callbacks, never in a continuous loop.
- File dialogs (`src/chooser.rs`, `src/app/dialog.rs`): xdg-desktop-portal-termfilechooser runs `portal/swayfin-wrapper.sh`, which starts `swayfin --choose open|multiple|directory|save PATH OUT` (config: `~/.config/xdg-desktop-portal-termfilechooser/config`, `create_help_file=0`). A bar under the list holds a label, the save name field, Open/Select/Save and Cancel; everything else works as usual. Picked paths are written to OUT one per line; exiting without writing cancels. Enter/the button enters a single selected folder, otherwise picks (selected files; the selected or current folder; the typed name). Double-clicking a file picks it or saves onto it; overwriting asks first. In save mode the name field has the keyboard until the list is clicked. The window's app_id is `swayfin-chooser` (floated by a rule in the sway config).
- `src/main.rs`: calloop event loop. File system work goes on a background thread and reports back through a calloop channel.

## Working with the user

- When in doubt about behavior or looks, ask multiple-choice questions instead of guessing.
- Don't write tests of any kind. The user tries changes by hand.
- `$mod+e` in Sway runs `target/release/swayfin`, so `cargo build --release` updates what it launches.
